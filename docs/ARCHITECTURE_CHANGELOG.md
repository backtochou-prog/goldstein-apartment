### Technical decisions

1. **Engine for the greybox: three.js + WebXR in a Vite app.** D1 (Godot native vs WebXR) is
   still yours to decide. The greybox needed to run and be tested now, and on this host only the
   web stack can be tested end to end: headless rendering, an emulated Quest 2 session, and
   collision. It is the same family as your existing `jumanji-vr` stack (three.js/WebXR). To keep
   D1 reversible, all geometry comes from one data spec, and the architecture exports to `.glb`,
   which Godot and Blender import directly.
2. **Dimensions are computed, not typed.** Every derived number comes from R01 pixels and named
   assumptions. Change an assumption (for example camera height after you find a set blueprint) and
   the whole apartment, docs tables (`npm run dims --md`) and tests follow.
3. **Status travels with geometry.** Every mesh carries `id`, `status`, `evidence` and `note` in
   `userData`. These are shown on click, used by evidence colouring, and exported in the glTF extras.
4. **Unknown is never drawn as architecture.** The fourth wall is a translucent, hatched
   **evidence limit**, labelled as not a film wall. The sisters' room, entrance and stairwell are not built.
5. **Separation.** Architecture, collision (invisible AABBs), evidence limits, furniture footprints,
   labels and reference cameras are separate groups. Inspection tools swap materials or toggle
   visibility only; geometry is never modified by inspection.
6. **Units and frame.** Metres; x from the left wall, z from the pocket-door wall, y up (see `APARTMENT_LAYOUT.md` §1).
7. **Privacy.** Dev server binds to localhost. `npm run dev:lan` (HTTPS, self-signed) is for a
   headset on your home network only. Reference photos are served from `../reference` at runtime and
   never copied into `dist/`. Nothing deployed.

### Known limitations

- **Not tested on a physical headset.** XR was tested only in the IWER emulator.
- The reprojection test checks that the implementation matches the solve. It is **not**
  independent proof of the dimensions, because they were derived from the same pixels. The
  independent evidence is the cross-checks in `ARCHITECTURE_RECONSTRUCTION.md` §2.
- R02, R04 and R05 cameras are **approximate** (unsolved). Their overlays will not line up exactly.
- Draw calls are not batched (69 meshes). That is fine for a greybox; merge static architecture before Phase 3 lighting.
- Window sashes, panelling, mouldings profiles and the barley-twist column are boxes or absent: detail is Phase 3.
- `app/tools/*-test.mjs` locate Playwright and IWER from `/root/jumanji-vr` when this project has none
  (override with `PLAYWRIGHT_MODULE` / `IWER_BUILD`). On another machine, install them or set those variables.
